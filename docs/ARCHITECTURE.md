# mipple architecture

mipple is "output A" of the design in [reference/oodle-rdo-ktx2.md](reference/oodle-rdo-ktx2.md#building-your-own-rdo--transcoder):
standard BCn blocks, RDO'd so a downstream LZ compressor shrinks them, stored in KTX2 + Zstd.
Nothing new runs at load time. The latent-space/transcoding path ("output B") is on the
[roadmap](ROADMAP.md).

```text
image ─► mips ─► base encode (parallel) ─► RDO (per 16/64 KiB chunk, LZ rate model) ─► KTX2 (+Zstd)
 surface   mips.rs   bc1.rs / bc4.rs / bc7/        rdo.rs                              ktx2.rs
                     format.rs dispatches; BC7 effort 0-1 runs 8 blocks per SIMD batch
```

## SIMD (`src/simd.rs`)

Kernels are written once, generic over `SimdF32` (with `SimdI32` and a mask type), and instantiated per
backend: `f32x8` (arrays; the build's baseline, SSE2 on x86-64 or NEON on aarch64) and `avx2::F` (`__m256`
intrinsics). Each kernel has a `#[target_feature(enable = "avx2,fma")]` wrapper, and `simd::level()` picks one
at runtime (`MIPPLE_SIMD=generic` forces the baseline). Method names follow `std::simd`, so moving to it once
`portable_simd` is stable is mostly a rename. Both backends do the same IEEE operations in the same order, so
results are bit-identical (tested), and there is no `mul_add` (a libm call without FMA hardware).

Two rules learned the hard way:

- **No closures or `array::from_fn` inside kernels.** A closure does not inherit `#[target_feature]`, so AVX2
  intrinsics inside one compile to real function calls. This made the first batch encoder 3× slower than scalar.
- **No hardware gathers for table lookups.** `lookup17` does 17-entry lookups with two `vpermps` and two blends;
  gathers are slow on many CPUs.

## Base encoders

All encoders minimize weighted SSE against the source with the format's channel weights
(`Format::error_weights`). `effort` (0–9, default 5) scales iterations and search width. BC4/BC5 use all ten
and BC1 levels; BC7 maps them onto a four-level search (`format::search_level`: 0–2, 3–5, 6–7, 8–9), and the
BC7 effort levels below are those search levels.

**BC1** (`bc1/batch.rs`): eight blocks per SIMD batch, one per lane, read straight from the surface like
BC4/BC5; every effort has its own search configuration (`bc1::batch::cfg`). Solid blocks use optimal
single-color tables. Effort 0 is a line fit (one power iteration, inset extremes, indices by projection) and
one least-squares refit; effort 1 keeps up to two refits when they lower the error. From effort 2 the lanes
are sorted along the principal axis with a sorting network, a 3-color cluster fit scores every split
with dark texels left to the black entry (KTX2 output is `VK_FORMAT_BC1_RGB_*`, whose alpha is ignored),
and a 4-color cluster fit (as in libsquish and icbc) scores contiguous splits: with prefix sums
`P`, a split's Σ(1−t)p is `(P[i]+P[j]+P[k])/3`, every lane scores the same split (in a frequency order
learned on the synthetic corpus, `bc1/order.rs`), and endpoints are snapped to 565 only when the split's
closed-form least-squares error (a lower bound, plus a tunable share of the expected snapping penalty) can
still beat some lane's best. Effort 4+ adds greedy ±1 endpoint moves under the exact error; effort 6+ a
second round sorted along the best endpoints' direction and exact evaluation of the best few splits. Every
candidate is kept per lane only when its exact error is lower. The scalar encoder (`bc1::encode`) remains as
the reference.

**ETC2 RGB** (`etc.rs`, scalar, one block at a time): every mode is tried and the lowest squared RGB error
wins. ETC1 (both flips, individual 444 and differential 555): a subblock's unclamped error splits into a
chroma term (how far the base color is from the subblock mean, off the gray axis) and a luma term that
depends only on the base's channel sum and the table, so lattice colors in a box around the mean are ranked
with one luma table per distinct sum and only the best few (2 at effort 0, 20 at effort 9) are scored
exactly, with clamping; differential pairs come from both subblocks' lists plus projections into the ±4
delta window, then least-squares refits of the chosen bases. T and H (effort 1+): two clusters from
principal-axis splits, colors from the cluster means, every distance, then alternating reassignment and
refit and, from effort 4, a ±1 descent on the 444 colors. Planar: a least-squares plane per channel and a
search of its quantized neighborhood, each channel on its own. **EAC** (`eac.rs`, the ETC2 RGBA8 alpha half
and R11/RG11): per table, the base and multiplier that span the block's range, a window around them, then
least-squares refits of (base, multiplier) to the chosen entries; 11-bit blocks are scored against the
8-bit source scaled to 11 bits with two fractional bits. No GPU kernel and no DDS (DXGI has no ETC formats).

**ASTC LDR** (`astc/encode.rs`, 4x4, 6x6 and 8x8): the only formats whose blocks are not 4x4 texels, so they
bypass the 4x4 `Block` path entirely: `pipeline` hands each mip level to `astc::encode::encode_surface` (one
block row per rayon task) and decodes with `astc::decode_rgba`, and `Format::encode_block`/`decode_block`,
`encode_base` and the 4x4 RDO pass panic for ASTC rather than run on the wrong footprint (ASTC has its own
pass, below). Each block is fitted
with a line in color space, the texels' positions on it become ideal weights, and those are decimated to
every weight grid the footprint allows by exact least squares (the infill taken as separable). Every (grid,
weight range, partitioning) candidate is ranked by an estimate of weight and endpoint quantization noise from
per-footprint mode tables; the best few (one at effort 0, one at 4x4 and two above at effort 1; more with effort) are
encoded exactly, with weights
re-derived from the quantized endpoints, then the closest few encodings (one at effort 0, up to 16 from effort 6)
each get a coordinate-descent polish and the best is kept, since polish reorders them. Each candidate's
weights are tried with direct endpoints (CEM 8 / 12), base+offset (CEM 9 / 13, the same number of values, more
precise for short segments) and base+scale (CEM 6 / 10: a line through black in four values, so a finer
endpoint range). Opaque layouts are also ranked as base+scale on their own, with the error off the best line
through black, so modes whose weights leave too few bits for six endpoint values still compete, and
multi-partition layouts with some partitions base+scale and the rest direct (per-partition CEMs, those
whose lines pass closest to black first). Two- and three-partition patterns and dual-plane layouts are
tried when the block is far enough from one line: the patterns that best agree with a k-means clustering
(a counting sort over per-pattern mismatches), from effort 1 the best 16 of those (from effort 2, 64; from effort 5, and effort 4 at 4x4, every
pattern; half as many above 16 texels) re-ranked by how far their texels lie from their partitions'
lines, each pattern's moments summed from a per-block table of every four-texel subset's. At 4x4 the estimates for two and
three partitions and a second plane are scaled down to match their measured exact errors. ASTC decodes differently in sRGB and linear mode, so the encoder is
told which (`BlockOpts::srgb`, on by default for color as with BC7). Output goes to KTX2 (vkFormat 157/158,
165/166, 171/172, DFD color model ASTC) or, one level only, a `.astc` file; DDS refuses it. No GPU kernel
yet.

**BC4/BC5** (`bc4/batch.rs`): eight blocks per SIMD batch, one per lane, read straight from the surface (eight
blocks of a block row are four 32-texel loads per row and a 4×4 transpose; no intermediate blocks), written as
raw bytes. Effort 0 projects texels onto the min/max line (Intel ISPC's method, with a threshold offset that
tracks the decoder's truncated palette) and packs indices with a `vpshufb` lookup. Effort 1 adds a
least-squares refit kept when it lowers the error. Efforts 2–9 are an exact search, bit-identical to the scalar
reference: both palette modes (6-value mode keeps literal 0 and 255), two refits, then an exhaustive endpoint
window of radius 0 (efforts 2–3), 1, 1, 2, 3, 4 (8–9), testing all eight palette entries per texel.

**BC7, scalar encoder** (`bc7::encode`, all efforts). Mode 6 for every block; at effort 1, blocks whose
per-channel standard deviation is below ~2 stop there (a bc7f shortcut). Then two-subset modes 1 and 3 (opaque)
or mode 7 (alpha), three-subset modes 2 and 0 (effort ≥ 2), and dual-plane modes 4 and 5 (alpha from effort 1,
opaque rotations from effort 2). Partitions come from `partition::residuals`: per subset, `trace(S) − λmax(S)`
of the scatter matrix is the squared distance to the best-fit line, a lower bound on any encoding's error
(every BC7 palette lies on a segment). Partitions are ranked per mode by that residual plus `Δw² · λmax`, an
estimate of index quantization error (`Δw` = index step), because on grayscale blocks every residual is ~0; the
residual alone is the pruning bound. The winner gets a greedy ±1 refinement of its quantized endpoints and
p-bits (`refine_endpoints`). Index search projects each texel onto the endpoint line and compares the nearest
palette entry and its neighbours (`LinePal`), taking the lowest index among equal errors, which keeps flat
regions LZ-friendly.

**BC7, fast encoder** (`bc7::fast`, every effort unless entropy reduction is on; tiers in `bc7::fast_cfg`).
Eight opaque blocks per SIMD batch read straight from the surface like BC1/BC4. Mode 6 first: principal axis
by three unnormalized power iterations, extreme projections, and quantization by one rounding per p-bit (a
mode-6 endpoint channel is the exact 8-bit value `2q + p`); each index is the better of the two palette
entries around the texel's projection under the exact RGB error (bc7e's method), and BC7's weight tables are
computed as `round(64 j / (n - 1))`; least-squares refits are kept per lane when they lower the error. Then,
for blocks with error left, modes 1 and 3 on each lane's candidate partitions: bc7f's estimate (split the
texels by the side of the mean along the principal axis, nearest partition by popcount), or all 64 ranked by
line-fit error (subset sums from per-nibble tables, λ from one power step off the block axis, plus the index
quantization term). Efforts 6-7 add 3-subset modes 0 and 2 (partitions ranked the same way over mode 0's 16
and mode 2's 64) and dual-plane mode 5 (each color channel in turn moved to the 8-bit scalar plane, the other
two fitted in 2-D). Each subset is fitted like mode 6 with per-lane membership masks. Each mode's best
encoding per lane competes with mode 6, and from effort 4 each lane's winner gets a ±1 refinement of
its endpoint levels and p-bits under the exact error (indices re-chosen per trial: fixing them loses two
thirds of the gain). Efforts 8-9 add bc7e's "uber" step (least-squares fits from index sets with the extremes
nudged inward and linearly stretched) and run it with the refinement on every mode's best encoding (and its
top candidates) before the modes compete. Mode-6 blocks are packed in registers; 2-subset winners with the scalar packer. Blocks
with alpha go to the scalar encoder.

**BC7, batch encoder** (`bc7::encode_batch`, search levels 0-1, opaque blocks; `pipeline::encode_base` uses
it when the fast encoder does not apply).
The same search on 8 blocks at once, one per lane, like ISPC-based encoders: mode 6 (PCA endpoints, p-bit-aware
quantization, projected index search, least-squares refits), then modes 1 and 3 on each block's 4 best
partitions (per-lane partition masks; lanes that cannot win are masked off and a step runs only if some lane is
active), then the ±1 refinement per mode group (single-endpoint moves only). Partition fits use one block per
lane too (`fits8`): membership is the same in every lane, so subset moments are plain sums, and λmax comes from
two short power iterations. Packing is scalar. Blocks with alpha go to the scalar encoder. It makes the scalar
encoder's choices except at near-ties.

**Entropy reduction** (`BlockOpts::reduce_entropy`, from bc7enc's `-e`). Candidates compete on a score where
only mode 6's error is weighted (×0.4 opaque, ×0.6 with alpha), and mode 6 endpoints are limited to 64 levels
per channel with fixed p-bits ((1, 1) opaque, (0, 1) with alpha). `EntropyMode` decides when to use it: `off`,
`on`, or `auto`, which means on from λ ≥ 1, where it beats plain encoding (see BENCHMARKS.md). RDO receives the same
flag (`RdoParams::reduce_entropy`) so its endpoint refits keep the restricted levels.

## RDO (`src/rdo.rs`)

RDO starts from a base encoding made at effort `RDO_BASE_EFFORT` (8) or more (`src/pipeline.rs`): for BC7
the plain search (as the base, or as a second base next to the entropy-reduced one, plus a mode-6-only base),
for BC4/BC5 the base itself (endpoint window radius 4; `base_block_opts`, which the GPU path uses too). RDO
keeps most of the accuracy a better base adds, and the base costs little next to RDO.

For each block in storage order:

1. Score the base encoding: `J = smooth · SSE / 16 + λ · bits`, where `bits` comes from `LzModel`.
2. For each of the last `max_back` blocks (capped by the window: 256 for BC1; 128 for BC4/BC5 and 16 for BC7,
   which add the localized search below), build candidates. Partial byte-span copies are only tried for the
   nearest `span_back` blocks (8 for BC1/BC4, off for BC5/BC7, where they cost time for no measurable gain): far
   away they rarely win, while whole-block and whole-field copies keep paying off at every distance.
   * **BC1:** copy the whole block; take its endpoints and re-choose indices; take its indices and refit endpoints.
   * **BC4/BC5:** the same per 8-byte half, plus both halves edited together and, when R and G are
     identical, the R half mirrored into G (keeps intra-block repeats Zstd relies on).
   * **BC7:** copy byte spans (endpoint region, index region, and several straddling spans), re-choose
     indices after endpoint copies, and take the previous block's indices and refit endpoints when mode and partition match.
   **Localized search (BC5, `local_k` 16):** beyond the nearest 128, rank every earlier block in the chunk by
   shape distance (mean-removed texels), keep 128, rank those with the MLP in `src/ranker/bc5.rs` (23 pair
   features, 16 hidden, deterministic SSE2/scalar inference), keep 16, and add the blocks around the one
   directly above (`row` ± 2). These go through the same exact candidate search; the network only picks where.
3. Skip work that cannot change the result: a previous block identical to a nearer one, BC1 endpoint or
   index fields an earlier previous block already had (their re-index or refit candidate would repeat; for
   BC4/BC5 halves the results are memoized by field value), and candidates already evaluated for this block
   (generation-tagged hash sets, cleared in O(1)).
4. Reject candidates whose error exceeds `max_rms_ratio² × base SSE + 16 × channels × min_rms²` (the per-block
   safety cap; `min_rms` = 3 gives blocks the base encodes almost exactly room to move),
   or whose distortion alone already loses, or whose distortion plus λ times a lower bound on any block's
   rate (the cheapest cover by the most frequent literal and repeat matches) already loses; rate is only
   estimated for survivors. BC1/BC4/BC5 errors come from fused kernels that read the palette directly and stop
   row by row once the error passes either bound; BC5 reuses the base block's half error for an unchanged half.
5. Keep the lowest `J`, append it to the model's history.

**Deferred decision (`defer` 0.3).** When a block's runner-up scores within 30% of its best, the choice waits
one block: the next block is searched after each of the two (the model is rolled back with
`LzModel::snapshot`/`undo` in between, the second pass re-pricing the first pass's candidates and searching only
the previous block), and the pair with the lower total `J` is kept. Choices whose bytes the next block can reuse
win more often than a greedy pass sees: −0.2% to −1.4% BD-rate at equal PSNR on every format, for about 1.05-1.3×
the RDO time. BC1 also scores the endpoints of the next 16 blocks and of the blocks around the one below,
re-indexed (−0.7%), so a block can establish a field its neighbours will share. BC7 skips the far search when
the near search already brought `J` under 0.8× the base's (−12% RDO time for +0.15%).

**Smooth-block protection.** Distortion is multiplied by `1 + (smooth_scale − 1) · k² / (k² + σ²)`, where σ is
the block's largest channel standard deviation and `k = smooth_std` (4× and 12 by default), because banding on
gradients is the most visible RDO artifact. Flat blocks get the full weight, a block at σ = k half the extra, and
busier blocks a tail that falls off smoothly (a linear ramp to 1 at σ 14 left gradual-but-textured blocks
unprotected and cost 2-3% at equal RMSE against Oodle Texture on BC7). When the row length is known (always through
the pipeline) the term is instead the mean of `k² / (k² + σ²)` over the four 8x8-texel windows that contain the
block, σ² the largest channel variance in each and `k = smooth_window_std` (16): the windows SSIM averages over,
so a flat block next to an edge is protected less and a busy block in a flat area more, in the spirit of x264's
adaptive quantization (−0.1% to −0.5% BD-rate at equal PSNR, −0.1% to −0.6% at equal SSIM, on every format).

**Rate model (`LzModel`).** Greedy LZ parse over a sliding window with hash chains, plus a scan for
matches inside the candidate itself. Literals cost order-0 entropy from the history; matches cost
`6 + log2(offset) + len_bits`; repeat-offset matches cost `3 + len_bits`; a repeat match that continues
the previous block's trailing match costs 1 bit (Zstd codes long runs as one match). Literal costs are
refreshed into a table once per appended block, and offset and length costs are tables too.

**Chunks and the safety net.** Blocks are optimized in independent chunks of `chunk_bytes` in parallel (16 KiB,
1024 BC5 or 2048 BC1/BC4 blocks; BC7 uses 64 KiB, 4096 blocks, with an 8 KiB window, because it gains most from
distant history and has time to spare against bc7enc_rdo). Chunks are sized in bytes so the window-sized stretch at each chunk
start that cannot see the previous chunk is the same fraction for every format, and independent of the thread
count so output does not depend on the machine. (Splitting each block's search over back distances across
threads, merged by lowest score with ties to the nearest candidate, gives identical output but did not pay on a
hybrid 155H: the per-block join waits for the slowest core, and the split loses dedup and pruning, +19% CPU.) After RDO, each chunk is compressed with real Zstd at the output
level; if it is not smaller than the base encoding, the chunk reverts. RDO therefore never increases the
shipped size, and every block respects the error cap.

**ASTC (`astc/encode/rdo.rs`).** ASTC blocks cover 4x4, 6x6 or 8x8 texels, so the pass reads each block's
texels from the surface instead of 4x4 `Block`s, with the same `J` (SSE over all four channels, `/ 16`, so a λ
means the same SSE per bit at every footprint), `LzModel`, error cap, 16 KiB chunks (1024 blocks) and Zstd
check. The base is the plain encode at the requested effort. A block's mode, partitioning and endpoints sit in
its low bits and its weights in its high bits, so the candidates are: an earlier block copied whole (the last
`max_back`, 256); and, from the last `REFIT_BACK` (256) blocks with at most three partitions sharing one CEM,
the earlier block's head with weights re-chosen for this block, and its weights (with mode, partitioning and
second-plane channel) with endpoints refitted by least squares (written direct), each polished once with the
other half held.
Heads and weight sets already tried are skipped. Before building either, a lower bound on its error must
beat the best `J`'s distortion: for a re-weight, each texel's distance to its partition's segment (a decoded
texel is within 0.5 per channel of a point on it); for a refit, the unclamped least-squares residual with the
weights held. Both bounds are exact, so they change no output; they make the pass 1.3-2.0× faster.

## Regression check (`src/check.rs`)

`mipple check` runs `bench::run_images` on an in-memory corpus: `synth::set()` at 256², or the first N images of
a directory. It turns each (image, format, λ) row into an `Entry`: PSNR, Zstd/Deflate bytes, FNV-1a of the
blocks, and seconds. Entries are written to or read from a baseline CSV (`#` header lines record corpus,
effort, entropy mode). The comparison pools each (format, λ) into one point: PSNR of the summed squared error,
with lossless results capped at 99 dB, and summed bytes. Then it applies these gates:

- BD-rate of the curve vs the baseline curve. Each curve is reduced to its Pareto front and ln(rate) is
  interpolated piecewise-linearly in PSNR (the same method as `scripts/bdrate.py`, used by `compete.py`). A least-squares
  cubic was used before; it swings wildly on short or non-monotonic RDO sweeps (it reported +15% for a BC1 curve
  that was smaller at every matched quality);
- λ = 0 pooled PSNR drop and size growth;
- per-image PSNR drop at λ = 0.

A baseline that doesn't cover the run's configurations is an error rather than a silent pass. Timing is
reported, and gated only with `--max-slowdown`.

## KTX2 (`src/ktx2.rs`)

Header → level index → DFD → key/value data (`KTXwriter`, `KTXwriterScParams`) → mip data, smallest mip
first. Supercompressed files use scheme 2 (Zstandard, one frame per level) and an "unsized" DFD
(`bytesPlane0 = 0`); raw files align levels to the block size. The DFD is byte-identical to the one the
`ktx2` crate generates for the same vkFormat (tested).
